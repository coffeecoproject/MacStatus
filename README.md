# MacStatus

本地 macOS 菜单栏应用，实时查看 CPU、内存、硬盘和温度。Swift 6，macOS 13+，无第三方依赖，不需要管理员权限；唯一的网络请求是 AI 页查询 Claude Code 额度。温度读取面向 Apple Silicon。

## 构建与运行

```sh
bash Scripts/build-app.sh
open .build/app/debug/MacStatus.app
```

构建脚本用钥匙串里的“Apple Development”证书签名，没有时用本地临时签名（ad-hoc），不需要付费开发者账号。用证书签名时 App 的身份在重新构建后不变，钥匙串里“始终允许”的授权保留；临时签名每次构建都会变，替换后会再问一次。生成本机自用 DMG：

```sh
bash Scripts/build-dmg.sh
```

输出为 `dist/MacStatus.dmg`，不公证，不作为跨机器分发包。

## 使用

- 菜单栏默认显示 CPU 使用率和 CPU 温度；右键（或 Control-单击）可勾选显示 CPU、温度、内存、硬盘，或退出。
- 左键展开面板，点击外部或按 Esc 收起；面板底部可退出。
- 外观跟随系统浅色 / 深色。

面板顶部分“概览”“进程”“清理”“AI”四页。概览分四块，每块有主数值和细项；CPU、温度、硬盘读写在主数值旁另有近 60 秒曲线：

| 模块 | 主数值 | 细项 |
| --- | --- | --- |
| CPU | 整机使用率 | 每核使用率（按能效核 / 性能核分组）、用户 / 系统占比、1/5/15 分钟负载 |
| 温度 | CPU 传感器最高值 | CPU 平均、GPU、固态硬盘、电池、系统散热状态 |
| 内存 | 已用占比 | App、联动、压缩、缓存构成条；交换区；系统内存压力 |
| 硬盘 | 启动卷已用占比 | 卷名、已用 / 可用 / 总量、读写速率 |

进程页只列可退出的 App（出现在程序坞的普通 App），按内存占用取前 10，显示占物理内存的比例，可直接退出；无法从这里操作的后台、菜单栏、命令行与系统进程不列出。

清理页顶部是可安全清理的总量，以及硬盘可用空间和清理后的可用空间；下面逐项列出开发工具缓存，每项可点“清理”并在同一行确认“移走”后移到废纸篓。`~/Library/Caches` 下其他较大的缓存默认折叠，展开后仅供参考，不能从这里删除。鼠标移到某一项上可在访达中显示它。

AI 页上半部是额度，下半部是正在运行的 Claude Code 会话：

- **Claude Code 额度**：5 小时和 7 天两个窗口的已用比例与重置时间，来自 Claude Code `/usage` 背后的额度接口（未公开，格式变了会显示“无法识别额度数据”）。用 Claude Code 存在钥匙串“Claude Code-credentials”里的登录信息查询：第一次读取时系统会询问是否允许，选“始终允许”后不再询问。读到的登录信息留在内存中复用，只在 App 启动后首次查询、登录信息过期或被接口拒绝时才重新读钥匙串。拒绝后不会自动再问，点“重试”才会。只读取、不续期登录信息（续期会替换 Claude Code 自己的登录），过期时显示“登录已过期”，等 Claude Code 下次使用时续上。
- **Codex 额度**：Codex 每轮对话后把额度写进 `~/.codex/sessions` 下的会话记录，读最新一份的末尾；不需要授权，没有网络请求。只在用 Codex 时变化，所以显示“N 小时前更新”。
- 读到的数据过了重置时间就显示“已重置”，不再显示旧的比例。读取失败时保留上一次的数据。
- **会话**：来自 Claude Code 在 `~/.claude/sessions` 下按进程登记的文件，进程已结束（或 pid 被其他进程复用）的不列出。显示标题、项目、工作中 / 空闲、运行时长和内存（含会话启动的工具与 MCP 服务进程）；悬停可在访达中显示项目目录。只读，不提供结束会话。

## 刷新

所有指标由一个时钟统一采集：面板展开时每 1 秒，收起时每 2 秒；展开面板会立即补采一次。CPU 使用率是相邻两次采样的差分，启动或唤醒后先建立基线，0.5 秒后给出第一个值。休眠时暂停，唤醒后重置 CPU 与磁盘读写基线。面板内容只在展开时存在，收起后不再随刷新布局和绘制；数值直接更新，不做过渡动画，以免每秒的刷新都在 CPU 上逐帧绘制。

App 内存列表只在进程页打开时读取：切到该页或打开面板时当场读取一次（约几毫秒），之后随刷新更新；离开该页或收起面板时清空。面板高度随内容变化（切换页面、App 启动或退出、展开折叠的列表）以短过渡动画调整，顶部保持贴在菜单栏下，内容不会上下跳动。

AI 页也只在打开时读取：会话每 2 秒读一次（几毫秒，切到该页时当场读取）；Codex 额度每 30 秒读一次；Claude Code 额度每 5 分钟最多查询一次（接口有频率限制）。离开该页或收起面板即停止。

清理页的扫描不在刷新时钟里：首次打开清理页时扫描一次，之后只在点“重新扫描”时扫描；扫描在后台进行，通常需要数秒到十几秒，期间显示按目录计的进度和正在扫描的目录（各目录大小差别很大，进度条在大目录上会停留较久）。

硬盘容量的“可用”含可清除空间，与访达一致，计算较慢（约 10ms），每 10 秒读一次；读写速率每次采样都读。

温度经 AppleSMC 只读接口单独读取，同一时间最多一个调用，结果随下一次采样一起更新，每次采样只刷新一次界面；超过 3 秒未返回则温度显示不可用，不影响其他指标。读取失败的指标显示“—”和“不可用”标记，不会保留旧值冒充当前值。

## 数据口径

- **CPU**：`host_processor_info` 每核 `(user + nice + system) / total`；核心类型来自 IORegistry 的 `cluster-type`。
- **内存**：与活动监视器一致，已用 = App（匿名页 − 可清除页）+ 联动 + 压缩；缓存 = 文件缓存页 + 可清除页。内存显示用二进制单位，硬盘用十进制单位（与访达一致）。
- **App 内存**：`proc_pid_rusage` 的物理占用（含压缩与已换出的页，同活动监视器“内存”列）。辅助进程按可执行文件所在的最外层 `.app` 并入所属 App，名称取 App 在 Info.plist 中声明的名称（同活动监视器）。只列正在运行的普通 App（同“强制退出应用程序”窗口，含嵌在 App 包内的，如 Docker.app 中的 Docker Desktop）；由系统代为运行的进程（如 Docker 的虚拟机、网页内容进程）不归入 App，因此不计入。只读当前用户的进程，无需管理员权限。“退出”效果等同在该 App 中选择“退出”，App 可能询问是否存储或拒绝退出；不提供强制退出。
- **清理**：大小为目录下文件实际占用的磁盘空间（同 `du`），不跟随符号链接。“可安全清理”只来自固定清单，都是删除后会自动重建、已安装内容不受影响的工具缓存：npm 下载缓存（`~/.npm/_cacache`）、pnpm、Homebrew、Playwright 浏览器（`~/Library/Caches` 下同名目录）、Xcode DerivedData、iOS DeviceSupport、模拟器缓存；不存在或为空的不显示。`~/.npm/_npx` 不在清单内，因为正在运行的 npx 程序会用到；模拟器设备应通过 Xcode 或 `xcrun simctl` 管理，也不在清单内。“其他大缓存”是 `~/Library/Caches` 下其余超过 100 MB 的目录，取最大的 8 个，由各 App 自行管理，只展示，不建议直接删除；名字以 `com.apple.` 开头的 Apple 自带缓存不读取，因为其中有受保护的数据（如 `com.apple.Music` 属于媒体库），读取会让系统弹出授权请求。Apple 另有少数不带该前缀的缓存目录，仍会被读取。“清理”只把清单内的目录整个移到废纸篓（可恢复，从不直接删除），移动前再次确认它是真实目录而非符号链接；清空废纸篓后空间才释放，因此“硬盘可用”在此之前不变。移走后自动重新扫描。确认在面板内进行，因为系统弹窗会抢走焦点并收起面板。
- **硬盘读写**：所有块存储设备 `IOBlockStorageDriver` 统计之和。
- **温度**：启动时枚举 SMC 键，`Tp*`/`Te*` 归为 CPU，`Tg*` 归为 GPU，`TH0x` 为固态硬盘，`TB0T` 为电池；只接受 `flt` 类型，读数不在 0–150°C 之间的传感器跳过。这些键没有苹果公开的兼容性承诺，macOS 或机型变化可能导致分组失效。

## 代码结构

- `MacSystemMetrics`：各指标读取器与纯计算（CPU 差分、内存构成、读写速率、SMC 报文、温度分组汇总、进程树内存）。
- `MacStatus`：`SystemMonitor` 调度与 60 秒历史；AppKit 菜单栏与面板；SwiftUI 卡片视图。
