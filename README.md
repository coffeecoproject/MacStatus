# MacStatus

显示 CPU 使用率、CPU 温度、内存用量、系统内存压力和启动磁盘容量的本地 macOS 菜单栏应用。Swift 6，macOS 13+，无第三方依赖、网络请求或管理员权限要求。当前面向这台 M2 MacBook Air；温度仅支持已确认的 Mac14,15。

## 构建与运行

在项目目录执行：

```sh
bash Scripts/build-app.sh
open .build/app/debug/MacStatus.app
```

构建脚本使用免费的本地临时签名（ad-hoc），不需要开发者账号，不公证或上传文件。生成本机自用 DMG：

```sh
bash Scripts/build-dmg.sh
```

输出为 `dist/MacStatus.dmg`，内含应用和 Applications 快捷入口。可自行复制应用到本地目录后运行；脚本不安装、不启动应用，也不修改系统安全设置。DMG 不提供 Developer ID 信誉或公证，不作为跨机器分发包。

脚本不会覆盖正在挂载的镜像。需要保留旧镜像时，可指定其他文件名，例如 `bash Scripts/build-dmg.sh MacStatus-0.1.0-local.dmg`。

菜单栏保持显示 CPU 数值，左键点击展开指标面板，点击面板外自动收起，监控继续运行。右键点击（或 Control-单击）菜单栏图标，选择“退出 MacStatus”停止应用；辅助功能提供“显示退出菜单”操作。不自动安装、不设置开机启动。

面板只显示指标数值、使用率进度条和压力状态，不设置关闭或退出按钮；CPU 温度为单行摄氏度数值，不添加温度进度条或阈值预警。不显示说明、更新时间或正常状态提示。采样中、不可用和暂停使用小图标区分，保留辅助功能标签。

面板无箭头，展示前先测量内容尺寸，再按所在屏幕的状态栏下沿定位并保持在可见区域内。面板控制器统一管理位置、外部点击收起、Esc 收起及采样频率切换，不依赖固定像素偏移。

## 数据与职责

- `MacStatusCore`：各指标的数值、状态、类型化错误、采集协议和整体快照，不依赖界面或 Mach。
- `MacSystemMetrics`：使用率、内存、硬盘与温度各自采集；CPU 使用率独立维护差分基线，计数计算与温度解码、汇总可独立验证。
- `MacStatus`：`SystemMonitor` 独占界面快照与采样策略，四个独立的 `MetricSampler` 管理各自任务、截止时间和生命周期；AppKit 管理菜单栏、弹出面板与系统生命周期，SwiftUI 分区展示状态。

采集器只报告错误，调度器负责重试，展示层格式化数值和简短状态。

CPU 使用率为相邻采样间的 `(user + system + nice) / total`，按整机归一到 0–100%，不是 load average 或单进程 CPU 百分比。

内存用量按 `(匿名页 - 可回收页 + 固定页 + 压缩存储页) × 内核页大小` 计算，不包含可回收文件缓存，不使用“总量减空闲”。容量以 GiB（1024³ 字节）显示。系统统计与其他工具的采样时刻可能不同。

内存压力读取本机系统等级，不按占用比例猜测。未知等级或压力读取失败时显示“不可用”，保留有效的内存用量；异常用量计数不会被强行修正成正常值。

硬盘容量读取启动磁盘卷的总容量与重要用途可用容量，显示为已用 / 总量 GiB。

CPU 温度是这台机器上已确认的四个性能核心传感器的最高读数，不代表全部 CPU 核心、整机外壳或电池温度。通过 AppleSMC 只读命令获取，不写硬件参数；每轮结束关闭连接。四个读数必须全部有效（有限且介于 0°C 与 150°C 之间），缺失、格式变化或异常值均显示“—”，不退化为部分传感器的最大值，不影响其他指标的成功读数。

AppleSMC 数据协议和传感器标识没有苹果的公开兼容性承诺，macOS 升级可能使温度读取失效。实现保留独立采集边界，不使用额外服务、管理员权限或 `powermetrics`。传感器映射参考 [Stats 的 M2 定义](https://github.com/exelban/stats/blob/489bf0ff4ca579467e557ff4f77cc16201a26d24/Modules/Sensors/values.swift)，仅采用本机已确认可读的性能核心键。

四项使用同一套间隔策略，但独立采集、完成后分别发布，不等待其他指标。展开时每项完成采集后等待 2 秒，收起后等待 5 秒，切换间隔不打断当前等待。CPU 启动、错误恢复及唤醒后先建立差分基线，下一次只对 CPU 缩短为 1 秒；内存、硬盘和温度不需要两次采样。

单项读取（含 CPU 基线重置）超过 3 秒仍未交付即标记超时，显示“—”。有效结果发布后最多保留 10 秒为当前值，过期也显示“—”；截止时间使用单调时钟，不依赖墙上时间或数值变化。失败、超时或过期只影响该项，保留的历史记录不会冒充当前值。

每项最多一个在途调用。取消不被视为调用已经结束：底层调用不响应取消时，不向同一采集器堆积重试；迟到结果丢弃，调用真正返回后重新采集，CPU 会先重置基线。若调用一直不返回，该项持续不可用，其他项继续刷新。休眠时分别暂停，唤醒时健康指标直接恢复，不等待另一项的旧调用；跨休眠结果不能覆盖新状态。

本阶段不包含风扇、历史报表或设置。

## 测试

```sh
swift test --enable-code-coverage
python3 -B -m unittest discover -s Tests/NativeUI -p 'test_*.py'
bash Tests/Packaging/verify-bundle.sh
```

打包检查默认验证应用元数据、可执行文件和本机架构，可通过 `--strict-signature` 检查完整本地签名。DMG 构建会执行完整签名检查与磁盘映像校验；验证脚本本身不修改签名。

原生界面脚本尚需将旧的弹出框识别方式适配为无箭头面板，并补充与状态栏的相对位置检查，暂不作为新版的界面验收依据。适配后的入口：`python3 -B Tests/NativeUI/run_owned.py --app .build/app/release/MacStatus.app`。需要终端已有辅助功能权限；脚本不会申请权限，遇到已有 MacStatus 实例会停止。它只启动、操作和退出自己的应用实例及临时点击窗口，鼠标点击前确认目标属于测试进程。检查期间不要移动鼠标、切换窗口或点击其他应用。

界面脚本检查启动不弹面板、左键开合、外部点击收起、右键/Control-单击菜单、取消与退出，以及四项指标、精简布局和裁切。持续展示时意外关闭会失败并保留焦点事件，不自动重复点击掩盖失败。采样测试覆盖各项分别挂起、超时、过期、迟到结果、重复暂停恢复及任务释放，不依赖可见时间戳或强求数值变化。

休眠恢复由模拟采集器验证调度逻辑，测试不会让电脑实际休眠。真实采集测试只读取系统计数和温度，不制造 CPU 压力；温度的真实采集测试面向本机 Mac14,15。
